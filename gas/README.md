# 投票用 Google 表單 + Apps Script 部署教學（非工程師也能跟著做）

這份教學會帶你完成「全場一起協助」投票功能需要的兩個東西：
1. 一個 Google 表單（觀眾用手機投票用）
2. 一個 Apps Script 網頁應用程式（大螢幕讀取票數統計用）

全部都在你自己的 Google 帳號底下完成，不需要寫程式。

---

## 第一步：建立 Google 表單

1. 到 [Google 表單](https://forms.google.com) 建立一個新表單，標題例如「猜謎現場投票」。
2. 加入**兩個問題**：
   - **第 1 題（簡答）**：標題填「題號」。這一題**不要**放在表單裡讓觀眾看到或填寫的位置太顯眼，因為它是靠網址「預先填好」的，觀眾投票時不需要自己輸入。
   - **第 2 題（單選或下拉選單）**：標題填「答案」，選項就是 `A`、`B`、`C`、`D` 四個。
3. **一定要按表單右上角的「發布」**：Google 表單新建時是草稿，沒有發布的話，觀眾打開連結只會看到「尚未發布」。發布時，「回覆者」要選「任何知道連結的人」。另外到「設定」分頁，把「收集電子郵件地址」設為不收集，並關閉「限制每人只能回覆 1 次」，否則觀眾會被要求登入。
4. **重要：表單裡不能出現正確答案，也不能出現題目內容。** 表單只負責收「這一題的題號＋觀眾選的字母」，不要把選項的文字內容也放進表單。

## 第二步：取得「預先填入的連結」網址樣板

1. 表單編輯畫面右上角有一個「⋮」（更多選項）或分享按鈕，點一下，選擇「**取得預先填入的連結**」。
2. 在「題號」那一題填入一個測試值，例如 `TEST-ROUND`，「答案」那一題可以先不填。
3. 點「取得連結」，會得到一長串網址，長得像：
   ```
   https://docs.google.com/forms/d/e/xxxxxxxxxxxxx/viewform?usp=pp_url&entry.111111=TEST-ROUND
   ```
4. 把網址裡 `TEST-ROUND` 那一段換成 `{round}`，例如：
   ```
   https://docs.google.com/forms/d/e/xxxxxxxxxxxxx/viewform?usp=pp_url&entry.111111={round}
   ```
   這個換好的網址就是 App 設定頁要填的「表單網址樣板」。App 之後會自動把 `{round}` 換成實際的題號。

## 第三步：開啟回應試算表

1. 回到表單編輯畫面，點「回覆」分頁，右上角有一個綠色的試算表圖示「建立試算表」，點下去。
2. 這會開一個新的 Google 試算表，裡面有一個分頁（通常叫「表單回應 1」），之後觀眾送出的每一筆投票都會自動出現在這裡。
3. **記住這個分頁的名稱**（預設是「表單回應 1」），下一步要用到。

## 第四步：貼上 Code.gs 與 parseChoice.gs

1. 在剛剛的試算表畫面，點選單「擴充功能」→「Apps Script」，會開一個新的分頁。
2. 畫面裡預設會有一個 `Code.gs` 檔案，把裡面內容全部刪掉，貼上專案裡 `gas/Code.gs` 的完整內容。
3. 點左側「檔案」旁的「+」→「**指令碼**」，新增一個檔案，命名為 `parseChoice`（副檔名 `.gs` 會自動加上），貼上專案裡 `gas/parseChoice.gs` 的內容。
   - 更簡單的做法：直接把 `parseChoice.gs` 裡的 `function parseChoice(...) {...}` 貼在 `Code.gs`（中文介面顯示為「程式碼.gs」）的最下面。同一個專案的函式彼此都叫得到，效果一樣。
4. 打開剛貼上的 `Code.gs`，找到最上面這一行：
   ```
   var RESPONSES_SHEET_NAME = "表單回應 1";
   ```
   確認雙引號裡的名稱跟第三步看到的分頁名稱完全一樣（如果不一樣要改成一樣，包括空格）。
5. 按上方選單「檔案」→「儲存」（或按 Ctrl+S / Cmd+S）。

## 第五步：部署為網頁應用程式

1. 在 Apps Script 編輯畫面右上角，點「部署」→「新增部署作業」。
2. 「選取類型」的齒輪圖示，選「**網頁應用程式**」。
3. 設定：
   - **執行身分**：**我**（你自己的帳號）
   - **具有應用程式存取權的使用者**：**任何人**
4. 點「部署」。第一次部署會要求你「授權」，跳出視窗後：
   - 選擇你的 Google 帳號
   - 如果出現「Google 尚未驗證這個應用程式」的警告，點「進階」→「前往（專案名稱）(不安全)」→「允許」。這是正常的，因為這是你自己寫的小工具，還沒有申請 Google 官方審核。
5. 部署完成後會顯示一個「網頁應用程式」網址，長得像：
   ```
   https://script.google.com/macros/s/xxxxxxxxxxxxx/exec
   ```
   把這個網址完整複製下來，這就是 App 設定頁要填的「統計網址（statsUrl）」。

> 之後如果修改了 `Code.gs` 或 `parseChoice.gs`，要記得回到「部署」→「管理部署作業」→ 點編輯（鉛筆圖示）→「版本」選「新版本」→ 部署，不然大螢幕讀到的還是舊的邏輯。

## 第六步：把兩個網址填進 App 設定頁

打開猜謎 App 的「設定」頁，找到「全場一起協助 / 投票設定」區塊，填入：
- **表單網址樣板**：第二步拿到、換成 `{round}` 的網址
- **統計網址**：第五步拿到的 `.../exec` 網址
- 勾選「啟用線上投票」

存檔後可以用「測試」按鈕（或直接開一場遊玩到投票環節）確認大螢幕能不能讀到票數。

---

## 已知限制（現場一定要知道）

- **延遲**：大螢幕每次查詢統計，大約會有 **2–5 秒**的延遲才能看到最新票數，這是 Google 表單／試算表本身的同步速度，無法消除，主持人可以口頭說「請大家投票，畫面數字更新會慢個幾秒」。
- **無法防止重複投票**：同一個人可以用同一支手機投兩次以上票，這個方案不做任何身分驗證。如果活動性質需要防止灌票，要另外想辦法（例如現場發一次性連結），目前版本沒有做。
- **人數上限**：建議現場投票人數在 **200 人以內**。如果預期人數更多，正式上場前務必先找多人（或用腳本）**做一次壓力測試**，確認 Google 表單和 Apps Script 在短時間大量送出時還撐得住，不夠穩就先切到主持人手動輸入模式。
- **表單網址不能包含答案**：務必再檢查一次，「取得預先填入的連結」網址裡除了題號以外，不能帶有正確答案或選項內容，否則觀眾打開表單的網址就能看到破綻（例如被眼尖的人看到網址列）。
- **只讀不寫**：`Code.gs` 只會讀取試算表，不會寫入或修改任何資料，可以放心操作。
- **網路不穩時的備援**：大螢幕連續 3 次讀不到最新票數，App 會提示切到主持人手動輸入模式，這時可以直接看手機（或請人數一下）用手動輸入百分比。
