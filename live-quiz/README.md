# 司法官學院 全場搶答（live-quiz）

活動現場 150 人用手機同時搶答（Kahoot 式），依分數選出前 3 名上台參加闖關猜謎。
主持人用電腦開投影畫面，觀眾掃 QR code 用手機作答，不用安裝任何 App。

- 正式網址：https://live-quiz.cosmos0409.workers.dev
- 主持人頁面：`/host`（投影用）
- 玩家頁面：`/play.html`（掃 QR code 會自動帶房間碼）

這套系統和專案根目錄的「闖關猜謎」是兩個獨立的程式，同一場活動先後使用。

---

## 架構

| 部分 | 技術 | 說明 |
|---|---|---|
| 網頁 | 原生 HTML／JS（沒有打包工具） | `public/`，由 Cloudflare Workers Static Assets 直接提供 |
| 伺服器 | Cloudflare Worker | `src/worker.js`：建立房間（`POST /api/rooms`）、WebSocket 轉交 |
| 房間 | Durable Object（SQLite） | `src/game-room.js`：一個房間一個 DO，名單、作答、分數都寫進 SQLite，休眠後也不會遺失 |
| 題庫驗證 | `src/question-bank.js` | 主持人上傳的題庫由伺服器最後把關 |
| 計分 | `src/scoring.js` | 答對 `round(1000 × (1 − 作答秒數 ÷ 時限 × 0.5))`，答錯 0 分，時間由伺服器計算 |

**安全設計**：題目本文與正解只傳給主持人，玩家手機只收到選項文字；主持人操作要附房間建立時產生的驗證碼。

## 資料夾

```
live-quiz/
├── wrangler.jsonc          # Worker 名稱、DO 綁定、SQLite migration
├── src/                    # 伺服器端（Worker、Durable Object、題庫驗證、計分、內建題庫）
├── public/                 # 網頁（host／play／index）、共用模組 shared/、院徽 brand/、題目圖片 img/
└── tools/                  # 測試與模擬工具（見下方「測試」）
```

## 第一次安裝

需要 Node.js 22 以上（內建 WebSocket，測試工具會用到）和 Cloudflare 帳號。

```bash
cd C:\猜謎程式\live-quiz
npm install
npx wrangler login
```

`wrangler login` 會開瀏覽器，要本人按同意授權。之後同一台電腦不用再登入（登入過期時，部署會自動再開一次）。

## 在自己電腦上執行

```bash
cd C:\猜謎程式\live-quiz
npx wrangler dev --port 8787
```

- 主持人畫面：http://127.0.0.1:8787/host
- 手機**連不到**這個網址（它只在這台電腦上），所以本機只適合看畫面、跑自動測試。要用手機測，請部署到正式網址。
- 修改 `src/` 或 `public/` 的檔案會自動重新載入。

## 部署到正式網址

```bash
cd C:\猜謎程式\live-quiz
npx wrangler deploy
```

成功時最後會出現 `Deployed live-quiz` 和正式網址。以下情況都要重新部署：

- 改了程式（`src/`、`public/`）
- 在 `public/img/` 放了新的題目圖片
- 改了內建題庫 `src/questions.js`

用試算表題庫時，**改題目不用部署**，建立新房間就會讀到新內容。

## 活動當天的流程（主持人）

1. 電腦開 `/host`，選題庫：
   - **內建題庫**：`src/questions.js` 裡的題目。
   - **Google 試算表「搶答題」分頁**：貼上分頁發布的 CSV 網址，按「讀取」。畫面會列出題目與秒數，**不會顯示正解**。
2. 按「建立房間」，畫面出現 QR code 與 6 位數房間碼，觀眾掃描加入。**建議在接投影機之前完成這一步**，避免試算表網址被投影出來。
3. 等待室會顯示所有暱稱。看到不當暱稱，點名字就能移出（出題中也可以按上方的「玩家名單」）。
4. 按「開始遊戲」。每題時間到、或全場都答完，會自動公布答案與前 5 名。按「下一題」繼續。
5. 最後一題結束後按「看最終排名」，頒獎台顯示前 3 名與 4 位數驗證碼。前 3 名的手機會顯示同一組驗證碼，上台時核對。

### 出狀況時

| 狀況 | 怎麼辦 |
|---|---|
| 主持人頁面不小心關掉或重新整理 | 重新打開 `/host`，會自動回到同一個房間、同一個畫面 |
| 主持人電腦壞掉 | 事先在主持人畫面按「複製接手連結」存起來（不要貼到公開的地方），在備援電腦打開就能接手 |
| 主持人斷線時剛好時間到 | 伺服器照常結算，重新連上後直接進入答案揭曉 |
| 玩家手機鎖屏、切換網路、重新整理 | 會自動重連，暱稱與分數都保留；只要還在時限內就能繼續作答 |
| 遲到的人 | 隨時可以加入，漏掉的題目算 0 分 |
| 試算表讀不到 | 會自動改用這台電腦上次讀成功時存下的版本，並寫出存下的時間 |

## 換題庫

### 方法一：Google 試算表（建議）

在「法官學院測驗表」的「搶答題」分頁新增或修改題目。欄位說明見 `../docs/題庫維護說明.md` 最後一節，範本是 `../docs/搶答題範本.csv`。

- 欄位：題目、圖片網址、A、B、C、D、正解、秒數、狀態
- C、D 可以留空，變成 2 選 1 或 3 選 1
- 最多 50 題；活動規格是 10 題 × 20 秒
- 題庫在建立房間的那一刻固定。改了試算表之後，要建立新房間才會用到新內容

### 方法二：內建題庫

編輯 `src/questions.js`（格式寫在檔案開頭），然後重新部署。

### 圖片題

1. 把圖片放進 `public/img/`，檔名用 `q01.jpg` 這種**不會透露答案**的名稱
2. 試算表「圖片網址」欄填檔名（例如 `q01.jpg`），也可以直接填 `https://` 開頭的網址
3. 重新部署

圖片只顯示在投影幕上，玩家手機不會收到。

## 測試

都在 `live-quiz/` 底下執行。不帶網址時測本機（要先開 `npx wrangler dev --port 8787`）。

| 指令 | 內容 |
|---|---|
| `node tools/bank-test.mjs` | 題庫解析與驗證（不需要伺服器） |
| `node tools/flow-test.mjs [網址]` | 完整流程：加入、作答、計分、重連、踢人、主持人恢復、上傳題庫 |
| `node tools/loadtest.mjs [網址] [人數]` | 壓力測試，預設 150 人；會印出延遲表 |
| `node tools/bots.mjs [網址] [人數] [房間碼]` | 讓模擬玩家加入某個房間自動作答，用來看主持人畫面 |

⚠️ **不要在活動當天對正式網址跑壓力測試。** 2026-09-14 的結果：正式環境 150 人，35 項檢查全部通過，最後一個答案送出後約 0.15 秒全場收到結算。完整報告在 `../docs/搶答系統-壓力測試報告.md`。

看正式環境的即時紀錄：

```bash
npx wrangler tail live-quiz --format pretty
```

## 免費額度

使用 Cloudflare 免費方案。以下數字是 2026-09-14 從 Cloudflare 官方定價文件查到的，之後可能調整，以官方文件為準。

| 項目 | 每天免費上限 | 一場（150 人 × 10 題）大約用掉 |
|---|---|---|
| Durable Object 請求 | 10 萬次 | 幾百次 |
| Durable Object 執行時間 | 13,000 GB-秒 | 約 25 GB-秒 |
| SQLite 寫入 | 10 萬列 | 約 1,500 列 |
| SQLite 讀取 | 500 萬列 | 很少 |

- 超過額度會直接出錯（不是變慢），每天台灣時間早上 8 點重置。
- 一天跑幾十場都不會超過；活動只需要 1–2 場。
- 查看用量：登入 Cloudflare dashboard，進入 Workers & Pages 裡的 `live-quiz`，看它的用量／指標頁面。（dashboard 的選單名稱可能會改版，找不到時搜尋「Durable Objects usage」）

## 疑難排解

| 現象 | 原因與處理 |
|---|---|
| 部署時跳出瀏覽器要登入 | 登入過期，按同意即可，部署會自動繼續 |
| 部署說找不到 `npx` 或 `node` | 從開始選單開新的 PowerShell 視窗再試 |
| 手機顯示「找不到這個房間」 | 房間碼打錯，或主持人按了「建立新房間」 |
| 讀取試算表顯示「拿到的是網頁，不是 CSV」 | 發布時格式要選「逗號分隔值檔案 (.csv)」 |
| 讀取試算表跳過某幾列 | 畫面上會列出「第幾列：原因」，照著修改試算表 |
| 被移出的人想回來 | 同一支手機回不來。確認是誤踢時，請他換一支手機或用瀏覽器的無痕模式重新加入 |

開發細節、已定案的決策與交接事項，請看 `../doc/handover.md`。
