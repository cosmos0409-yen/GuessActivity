# 全場搶答系統 — 150 人壓力測試報告（階段 4）

> 測試日期：2026-09-14
> 測試腳本：`live-quiz/tools/loadtest.mjs`（在 `live-quiz/` 執行 `node tools/loadtest.mjs [網址] [人數]`）
> 測試環境：本機 `wrangler dev`（wrangler 4.131.1、Node 24、Windows 11），1 位主持人＋150 位模擬玩家，全部從同一台電腦連線

## 結論

- **150 人同時加入、作答、結算都沒有問題**：35 項正確性檢查全部通過，全程沒有任何錯誤訊息。
- **結算速度遠低於人能察覺的程度**：最後一個答案送出後，150 支手機在 0.05 秒內全部收到結果。
- **正式環境（Cloudflare）也全部通過**：使用者在 2026-09-14 部署（版本 `94ddea51-e66a-41c7-a5c0-2ddd2c92596c`），並對正式網址跑 150 人，35／35 通過，結算在 0.17 秒內送達全部手機。

## 免費額度用量（估計）

一次完整壓力測試大約寫入 SQLite 500 列（150 人加入＋約 360 筆作答），DO 請求數百次。免費額度是每天寫入 10 萬列、請求 10 萬次，一天跑幾十次都不會超過。**活動當天仍然不要對正式網址跑**，以免和真正的觀眾搶資源。

## 還沒測到的部分

- **正式環境**：部署之後要對正式網址再跑一次（指令見下），確認真實網路下的延遲。
- **真實手機的行動網路**：模擬玩家都在同一台電腦上，測不出手機鎖屏、切換 Wi-Fi／4G 的情況。這次在前端加上了「連線假死偵測」（ping 送出 8 秒沒有回應就換新連線）和「網路恢復時立即重連」，需要用真的手機測試。
- **150 條連線來自同一個 IP**：現場是 150 支不同的手機，這個差異對伺服器是有利的，不會更慢。

```bash
node tools/loadtest.mjs https://live-quiz.cosmos0409.workers.dev 150
```
